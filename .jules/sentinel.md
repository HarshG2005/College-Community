## 2024-05-24 - [Replaced Synchronous File Operations]
**Vulnerability:** Found `fs.readFileSync`, `fs.existsSync`, `fs.unlinkSync`, and `fs.appendFileSync` being used inside Express route handlers (`server/controllers/resumeController.js` and `server/agent/tools.js`). These synchronous file operations block the Node.js event loop while executing, leading to Denial of Service (DoS) vulnerabilities if the server handles concurrent requests or large file operations (e.g., PDF parsing and logging).
**Learning:** Using synchronous I/O in asynchronous event-driven environments like Node.js severely impacts scalability and responsiveness, creating a bottleneck that can be exploited by an attacker to cause resource exhaustion. Replacing them with their asynchronous equivalents from `fs.promises` maintains the intended file system operations while preventing event-loop blocks. Wrapping `unlink` in a `try...catch` and skipping `existsSync` check further prevents race conditions.
**Prevention:** Avoid using synchronous functions from the `fs` module (methods ending with `Sync`) in backend route handlers. Always prefer asynchronous alternatives (e.g., `fs.promises.readFile`, `fs.promises.unlink`, `fs.promises.appendFile`) to ensure the event loop remains unblocked.
