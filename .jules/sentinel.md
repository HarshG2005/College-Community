
## 2024-05-24 - [Replaced Blocking Sync FS Calls with Asynchronous Equivalents to Prevent DoS]
**Vulnerability:** Synchronous file operations like `fs.readFileSync`, `fs.unlinkSync`, and `fs.appendFileSync` were being used inside Express route handlers and agent tools. This allows attackers to perform a Denial of Service (DoS) attack by spamming requests that block the single-threaded Node.js event loop, preventing the server from handling other legitimate user requests. Furthermore, `fs.existsSync` combined with `fs.unlinkSync` created a Time-Of-Check to Time-Of-Use (TOCTOU) race condition.
**Learning:** Node.js backend systems should rarely, if ever, use synchronous file system operations in request paths. This is a common pattern that developers often overlook when writing "quick" scripts or fallback logging mechanisms, but it scales poorly and introduces severe application availability risks.
**Prevention:** Always use `fs.promises` for non-blocking asynchronous file operations inside route handlers or async logic. Do not check for file existence before deletion; instead, try to delete the file asynchronously and handle the `ENOENT` error if the file was already removed to prevent TOCTOU bugs.
