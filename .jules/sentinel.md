## 2025-02-18 - Uncast Query Parameters causing Type DoS and NoSQL Injection
**Vulnerability:** Express route handlers across the application (e.g., in `auth.js`, `events.js`, `notices.js`, `placements.js`) accessed properties on `req.query` and `req.body` and immediately called string methods like `.toLowerCase()` or passed them to MongoDB operations like `new RegExp()` or `$text: { $search: ... }` without validating their type. This allowed an attacker to supply arrays or objects instead of strings (e.g., `?category[]=A`), triggering unhandled `TypeError` exceptions that crashed the server (Denial of Service). It also allowed NoSQL Injection vectors (e.g., via `$text` and MongoDB `findOne`).
**Learning:** In Express, `req.query` and `req.body` parameters are inherently untyped and can be parsed as arrays or objects depending on the query string/JSON payload formatting. The `express-validator` middleware does not enforce types unless specifically coerced (e.g. `matchedData()`), and Mongoose models do not protect logic before query execution. Calling string-specific methods on untrusted input without explicitly casting or checking the type is an anti-pattern.
**Prevention:** Always explicitly cast user-supplied input to a string (e.g., `String(input)`) *before* invoking string methods (like `.toLowerCase()`) or injecting it into database queries, particularly when constructing Regular Expressions or dynamic MongoDB queries. Additionally, escape regular expressions properly.
