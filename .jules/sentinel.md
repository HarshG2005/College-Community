## 2024-05-31 - [Placements API: Uncast Query Parameters Causing ReDoS, Type DoS, and NoSQL Injection]
**Vulnerability:** In `server/routes/placements.js`, `req.query.company` was passed directly into `new RegExp(company, 'i')` without string casting or escaping, exposing the endpoint to ReDoS via crafted regex payloads and Type DoS via array/object inputs. Furthermore, `req.query.type` and `req.query.search` were not explicitly cast to strings, allowing Type DoS (from `.toLowerCase()`) and NoSQL injection (from MongoDB `$text` search receiving an object payload).
**Learning:** Even when query parameters are used as inputs for object creation like `new RegExp()`, they must be explicitly cast to strings and appropriately sanitized (e.g., regex escaping). Uncast objects or arrays can break the constructor or lead to unintended behavior, while unescaped strings can cause severe performance degradation (ReDoS).
**Prevention:** Always explicitly cast user inputs (like `req.query` or `req.body`) to strings and apply necessary escaping before using them in constructors (like `RegExp`), string methods, or database queries, to prevent injection and DoS risks.
