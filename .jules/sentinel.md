## 2024-05-15 - Unsanitized User Input in Regular Expressions (ReDoS) and Type Confusion DoS
**Vulnerability:** The `company` parameter in `req.query` was passed directly into `new RegExp(company, 'i')` without escaping, leading to a Regular Expression Denial of Service (ReDoS) vulnerability. Additionally, properties like `type` and `req.params.id` were vulnerable to Type Confusion DoS and NoSQL injection because Express can parse them as arrays or objects, causing `.toLowerCase()` and MongoDB queries to behave unexpectedly.
**Learning:** Never pass unescaped user input into `new RegExp`. Furthermore, always explicitly cast parameters from `req.query` or `req.params` to `String` when expecting a string, as Express.js does not guarantee query/parameter types.
**Prevention:** Use an escaping function (e.g., `String(input).replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`) for any user input used in regexes. Explicitly cast Express request parameters to `String(...)` before calling string methods or using them in database queries.
