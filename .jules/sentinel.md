## 2024-11-20 - Synchronous File Operations in Async Handlers
**Vulnerability:** Use of synchronous file system operations (e.g., `fs.readFileSync`, `fs.unlinkSync`, `fs.appendFileSync`) in asynchronous route controllers (`analyzeResume`) and AI agent tools.
**Learning:** Node.js runs on a single-threaded event loop. Synchronous operations block this loop, causing all concurrent requests to stall until the file operation completes. This leads to severe performance degradation and constitutes a significant Denial of Service (DoS) risk, especially with larger files (like PDFs) or high request volumes. Checking for file existence before deletion using `fs.existsSync` also introduces a race condition (Time-of-Check to Time-of-Use).
**Prevention:** Always use asynchronous file system operations (e.g., `fs.promises.readFile`, `fs.promises.unlink`, `fs.promises.appendFile`) inside async handlers. When deleting files, instead of checking for existence first, wrap the `await fs.promises.unlink()` in a try-catch block and ignore the `ENOENT` (file not found) error.
