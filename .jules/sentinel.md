## 2024-10-07 - Type DoS, ReDoS, and NoSQL Injection via Uncast Route Parameters
**Vulnerability:** Type DoS, ReDoS, and NoSQL injection vulnerabilities were present across multiple Express routes (like `placements.js`). This occurred because user inputs from `req.query` and `req.body` were not explicitly cast to strings before being processed by string methods like `.toLowerCase()` or passed into the `new RegExp()` constructor and Mongoose queries (e.g., `$text: { $search: query }`). For example, passing an array to `req.query.type` causes a Type DoS crash when `.toLowerCase()` is called. Passing an unescaped string to `new RegExp()` allows ReDoS. Passing an object to `$search` allows NoSQL object injection.
**Learning:** In this codebase, the lack of a global security middleware means all route parameters must be manually verified. Express route parameters (`req.params`) are inherently strings, but `req.query` and `req.body` parameters are not guaranteed to be strings and must be explicitly cast (e.g., `String(param)`) to prevent malicious object or array payloads from causing unexpected behavior or crashes.
**Prevention:** Always explicitly cast `req.query` and `req.body` inputs to strings (e.g., `String(req.query.param)`) before calling string methods on them or passing them into Mongoose queries. When using `new RegExp()`, always escape regex special characters (e.g., `.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`) to prevent ReDoS. When using express-validator, consider using `matchedData()` to ensure coerced data is used.
