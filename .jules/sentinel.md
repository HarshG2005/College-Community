## 2024-05-24 - Missing Input Casting Causes ReDoS, Type DoS, and NoSQL Injection
**Vulnerability:** The API endpoints (`server/routes/placements.js`) accept `type`, `company`, and `search` query parameters. These parameters are directly used to construct database queries and are passed to `.toLowerCase()` or `new RegExp()` without validation or explicit casting. An attacker can pass an object or an array as a query parameter (e.g. `?type[]=...` or `?company[$ne]=...`), which bypasses truthy checks. Passing an array or object to `.toLowerCase()` can cause a Node.js process crash (Type DoS). Furthermore, `new RegExp()` can be exploited with a heavily crafted string containing unescaped characters leading to ReDoS (Regular Expression Denial of Service). Also passing an object into `$text` causes NoSQL Injection.
**Learning:** In a dynamically-typed environment like Node.js + Express, without validation middleware enforcing data types, input parameters can arbitrarily mutate into objects/arrays. Express route parameters (`req.params`) are strictly strings, but query (`req.query`) and body parameters (`req.body`) require explicit casting.
**Prevention:** To prevent these vulnerabilities across the API, always cast the input variable into a primitive string `String(val)` before performing string operations (e.g., `String(val).toLowerCase()`) and ensure that all special regex characters are escaped when dynamically constructing regular expressions for database searches (e.g. `String(company).replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`).
