## 2024-05-24 - Unsanitized Express Route Parameters Vulnerability
**Vulnerability:** Type DoS, ReDoS, and NoSQL injection vulnerabilities exist across multiple Express routes (e.g., `placements.js`, `events.js`, `notices.js`, `auth.js`, `materials.js`). The application accepts uncast user inputs from `req.query` and `req.body` and directly uses them in string operations (like `.toLowerCase()`), `RegExp` constructors, and MongoDB `$text` searches.
**Learning:** Because the app lacks global validation/sanitization middleware for query parameters and body payloads, objects or arrays can be passed in where strings are expected. This leads to crashes when string methods are called on them (Type DoS), ReDoS when unescaped strings are passed to regex constructors, and NoSQL injection when objects are evaluated as database queries. Express `req.params` are safe as they are inherently strings, but `req.query` and `req.body` are not.
**Prevention:** Always explicitly cast `req.query` and `req.body` parameters to `String` (e.g., `String(req.query.param)`) before calling string methods or passing them to database queries. When using `RegExp` with user input, explicitly cast to string and escape regex special characters (e.g., `.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`).
