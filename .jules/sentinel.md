## 2024-05-18 - Type DoS via uncast inputs to string methods
**Vulnerability:** Type Denial of Service (DoS) and potential NoSQL injection vulnerabilities were present across multiple route handlers (e.g., `events.js`, `notices.js`, `materials.js`, `auth.js`, `placements.js`). The application invoked string methods like `.toLowerCase()` and `new RegExp()` directly on user-supplied query and body parameters without explicitly verifying their type. If an attacker supplied an array or object payload (e.g., `?category[]=Tech` or `?company[$ne]=null`), the application would crash with a TypeError (e.g., `category.toLowerCase is not a function`), enabling an unauthenticated Denial of Service attack against the API.
**Learning:** Frameworks like Express map query parameters and JSON body payloads directly to potentially unexpected types (arrays or objects). Validation middleware like `express-validator`'s `isEmail()` may sometimes be bypassed or fail to sanitize inputs into strings natively unless explicitly configured to do so (e.g. using `matchedData`). Furthermore, passing an unescaped, uncast parameter into `new RegExp(param, 'i')` introduces a Regular Expression Denial of Service (ReDoS) vulnerability.
**Prevention:** Always explicitly cast user inputs (except inherently string-based route parameters like `req.params`) to `String` (e.g., `String(req.query.category).toLowerCase()`) before performing string operations or database queries to safely neutralize type mismatches and prevent NoSQL object injection. For regular expressions derived from user input, combine string casting with a robust escaping mechanism (e.g., `String(input).replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`).
