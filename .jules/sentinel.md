## 2024-05-24 - Missing Input Casting in Express Routes causes Type DoS and NoSQLi
**Vulnerability:** Several route files (auth.js, events.js, notices.js, materials.js, placements.js) accepted `req.query` and `req.body` variables without casting them to Strings. Passing object payloads to these variables (e.g. `?search[$ne]=...`) caused Type DoS crashes when `.toLowerCase()` was called, and permitted NoSQL injection when used in database queries. Additionally, passing objects to the `RegExp` constructor in `placements.js` could cause ReDoS or unexpected matching.
**Learning:** Express `req.query` and `req.body` parameters are not inherently strings; they can be objects or arrays if the client crafts the request that way. Passing these directly to string methods or database queries is inherently unsafe without global validation middleware or manual casting.
**Prevention:** Always manually cast `req.query` and `req.body` parameters to `String` (e.g., `String(search)`) before performing string operations (like `.toLowerCase()`) or passing them into Mongoose queries, especially for operations like `$text` search or `RegExp`. Always escape regex specials if dynamically constructing RegExp objects from user input.
