## 2024-05-24 - Unsanitized User Input in Express Query Parameters
**Vulnerability:** Type DoS, NoSQL Injection, and Regular Expression Denial of Service (ReDoS) vulnerabilities across Express routes where `req.query` and `req.body` parameters are directly passed to string methods (like `.toLowerCase()`), Mongoose constructors (like `$text: { $search }`), or the `RegExp` constructor without explicit casting or escaping.
**Learning:** `req.query` and `req.body` in Express can be parsed as objects or arrays instead of strings (e.g., `?param[$ne]=val` or `?param=1&param=2`). Calling string methods on them can cause crashes (Type DoS). Passing objects directly to Mongoose queries can lead to NoSQL injection. Passing unescaped input to `RegExp` allows attackers to craft complex regex that consumes excessive CPU (ReDoS).
**Prevention:** Always explicitly cast user inputs from `req.query` and `req.body` to a String (e.g., `String(req.query.param)`) before calling string methods or passing them to Mongoose queries (unless Mongoose handles the type casting automatically). For Regex creation, explicitly escape special characters (e.g., `.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`) before passing the string to the `RegExp` constructor. Note: `req.params` are guaranteed to be strings by Express, so they do not strictly require this casting.
