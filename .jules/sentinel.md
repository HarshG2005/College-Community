## 2024-05-24 - DoS and NoSQL Injection via Unsanitized Query Parameters
**Vulnerability:** Across multiple routes (`events.js`, `materials.js`, `notices.js`, `placements.js`), `req.query` properties (like `category`, `search`, `subject`, `type`) were being used directly in MongoDB queries and String methods (`.toLowerCase()`) without type checking or casting. This allowed NoSQL injection via object payloads (e.g., `?category[$ne]=All`) and Denial of Service (DoS) crashes if an object or array was passed, causing `.toLowerCase()` to throw a TypeError. Furthermore, the `company` parameter in `placements.js` was passed directly to `new RegExp()` without escaping, creating a Regular Expression Denial of Service (ReDoS) vulnerability.
**Learning:** In the absence of a global validation middleware or a strict framework-level type coercion (like TypeScript or Zod), Express/Node.js route parameters can be arrays or objects, not just strings. Assuming they are strings leads to critical stability and security issues.
**Prevention:** Always explicitly cast `req.query` and `req.params` variables to Strings (e.g., `String(param)`) before performing string operations or passing them to database queries. When using user input in regular expressions, always apply standard regex escaping (e.g., `.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`).
