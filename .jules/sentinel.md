## 2024-05-18 - Express Router NoSQL and ReDoS Injection via Unescaped Regex
**Vulnerability:** The `req.query` parameters `type`, `search`, and `company` were not explicitly cast to strings before usage in route handlers. In `server/routes/placements.js`, the `company` parameter was passed directly to a `new RegExp(company, 'i')` construct. This allowed a malicious user to supply an array payload `?company[$ne]=val` or `?company[]=...` which bypassed simple truthy checks, resulting in Type DoS when string methods like `.toLowerCase()` are applied. More critically, passing unescaped user input to `new RegExp` allows Regular Expression Denial of Service (ReDoS) by passing complex regular expressions that consume excessive CPU, and NoSQL Injection if regex control characters are injected into database queries.
**Learning:** Due to the lack of global security middleware that coerces `req.query` and `req.body` to strings, all such inputs must be manually cast to `String` (e.g., `String(req.query.param)`) before string operations. User inputs used in Mongoose `$regex` queries or `new RegExp` constructions MUST be explicitly escaped.
**Prevention:** Always explicitly cast user inputs from `req.query` and `req.body` to strings before using string methods. Before passing user input into `new RegExp` or Mongoose `$regex`, strictly escape the input using `String(input).replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`.
