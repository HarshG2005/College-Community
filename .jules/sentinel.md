## 2024-05-18 - Fix Blocking Synchronous File Operations
**Vulnerability:** Found synchronous file operations (`fs.readFileSync`, `fs.appendFileSync`, `fs.unlinkSync`) in `server/controllers/resumeController.js` and `server/agent/tools.js`. These operations block the Node.js event loop, preventing the server from handling concurrent requests.
**Learning:** Even within `async` functions or when interacting with APIs (like Gemini), using synchronous filesystem methods introduces a Denial of Service (DoS) vulnerability in Node.js applications because the event loop is single-threaded. Wrapping `fs.existsSync` and `fs.unlinkSync` is an anti-pattern prone to race conditions.
**Prevention:** Always use the asynchronous, Promise-based `fs.promises` equivalents (`readFile`, `appendFile`, `unlink`). When deleting files, instead of checking if they exist first, perform the `await fs.promises.unlink(...)` directly and catch the resulting error (if any) to prevent Time-of-Check to Time-of-Use (TOCTOU) bugs.
