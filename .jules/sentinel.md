## 2024-10-29 - Type DoS and ReDoS in Mongoose queries using req.query
**Vulnerability:** The API passed `req.query` variables directly to `String.prototype.toLowerCase()`, Mongoose `$text` searches, and `new RegExp()` without validation or string coercion. This allowed an attacker to send object payloads (e.g., `?type[$ne]=`) leading to Type DoS errors (since objects don't have a `.toLowerCase()` method) or pass crafted patterns to `new RegExp` causing ReDoS.
**Learning:** In Express, properties within `req.query` and `req.body` are not strictly strings; they can be parsed as objects/arrays if formatted a certain way (e.g., `?search[key]=value`). Relying on implicit assumptions about types when interacting with regexes or String prototypes in Node/Mongoose creates critical Type DoS, NoSQL injection, and ReDoS risks. Mongoose doesn't strictly sanitize regex inputs when passed via `new RegExp`.
**Prevention:** Always explicitly coerce `req.query` and `req.body` user inputs to `String()` when performing string operations (like `.toLowerCase()`) or when using `$text` searches. Furthermore, before placing user input into a dynamic regular expression (`new RegExp()`), ensure the string is sanitized by escaping regex special characters (e.g., using `.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`) to prevent ReDoS.
