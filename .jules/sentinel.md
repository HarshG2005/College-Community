## 2024-05-24 - [Express-Validator Bypass and Implicit Type DoS]
**Vulnerability:** Type DoS and NoSQL injection vulnerabilities were present across multiple Express routes due to implicit trust in `req.query` and `req.body` payload types, specifically assuming they were strings when calling `.toLowerCase()` or passing them to MongoDB `$text` queries. Furthermore, `express-validator` (e.g., `isEmail()`) can bypass validation for arrays if the first element passes, allowing an array to slip through and crash the application when `.toLowerCase()` is called on it.
**Learning:** `req.query` and `req.body` parameters in Express can be unexpected objects or arrays unless strictly parsed or inherently string-based (like `req.params`). Using `express-validator` does not automatically coerce types into strings unless `matchedData` is used, leaving the raw `req.body` vulnerable to Type DoS if string methods are called directly.
**Prevention:** Always explicitly cast user inputs from `req.query` and `req.body` to strings (e.g., `String(param)`) *before* executing any string methods like `.toLowerCase()` or passing them into potentially sensitive queries to prevent crashes and NoSQL injections.
