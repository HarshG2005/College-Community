## 2024-08-23 - Prevent Type DoS and NoSQL injection in Route Inputs
**Vulnerability:** Express `req.query` and `req.body` parameters are inherently untyped and can be parsed as objects or arrays by middleware. When these uncast parameters are passed directly into string operations like `.toLowerCase()`, `new RegExp()`, or Mongoose `$text`/`$search` queries, attackers can send array or object payloads (e.g., `?search[$ne]=1`) to bypass intended logic, inject NoSQL queries, or crash the server via Denial of Service (Type DoS) when string methods fail on objects.
**Learning:** We must not assume `req.query` and `req.body` are strings. `express-validator` and simple existence checks (`if (category)`) do not guarantee string types.
**Prevention:** Always explicitly cast potentially unsafe user inputs to strings using `String(param)` before performing string manipulations or passing them into Mongoose queries, especially for complex operators like regex and full-text search. This practice explicitly normalizes input and prevents object/array injections from crashing the server or modifying query structures.
