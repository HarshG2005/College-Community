## 2026-07-13 - [HIGH] Fix Type DoS, NoSQL injection, and ReDoS vulnerabilities
**Vulnerability:** Multiple routes (auth, events, notices, placements, studyPlanner) passed uncast `req.query` and `req.body` parameters directly to string methods (like `.toLowerCase()`, `.replace()`) or MongoDB queries. This could cause Type Denial of Service (DoS) if unexpected object/array payloads are sent, NoSQL injections (via $ne, $gt object payloads), or Regular Expression Denial of Service (ReDoS) if inputs with special regex characters weren't escaped before `new RegExp()`.
**Learning:** Due to the absence of global security middleware casting payloads to strings, and the fact that express-validators like `isEmail` can mistakenly pass array payloads (e.g. `["test@example.com", "other"]`), these endpoints were highly vulnerable. Native Node.js `ERR_MODULE_NOT_FOUND` on testing indicated `node_modules` wasn't properly initialized, requiring `node -c` for validation instead of full tests.
**Prevention:** Always explicitly cast user input parameters (like `String(input)`) before applying string methods or using them in MongoDB/Mongoose queries or RegExp constructions. Always explicitly escape string characters for `new RegExp()` using `.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`.
