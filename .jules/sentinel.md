## 2024-11-23 - ReDoS, Type DoS, and NoSQL Injection via Uncast Express Query Parameters in Placements
**Vulnerability:** The `/api/placements` endpoint consumed `req.query.type`, `req.query.company`, and `req.query.search` directly without type validation. `company` was used in `new RegExp(company, 'i')` allowing for Regular Expression Denial of Service (ReDoS) via complex malicious regex patterns, and potentially NoSQL regex injection if an object was passed. Calling `.toLowerCase()` directly on `req.query.type` and passing `req.query.search` into a `$text` search could lead to Type DoS (server crashes) or NoSQL injection respectively when an unexpected type (e.g., array or object) is received.
**Learning:** In Express apps missing global security middleware, `req.query` and `req.body` parameters are untyped and can be arrays or objects (if maliciously crafted or inadvertently sent as such). Operations expecting strings (like `new RegExp()`, `.toLowerCase()`, and MongoDB `$text` search) will throw or behave unexpectedly if these are not explicitly cast to Strings.
**Prevention:** Always manually cast `req.query` and `req.body` parameters to `String()` prior to calling string prototype methods or passing to Mongoose queries that expect primitives (like `$text`). For user input destined for `RegExp`, after string casting, the input must also be sanitized using a regex escaping function (e.g., `String(input).replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`) to prevent ReDoS.
